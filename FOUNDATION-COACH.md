# Strength-first running foundation — 2026-11-09

## User direction
Withdraw the December 2026 race goal, prioritize strength and muscle definition, and build running tolerance for an undated 2027 race. Tuesday and Friday remain unavailable. Do not infer whether the future distance is a half or full marathon.

## Baseline rhythm
Monday upper-body strength; Tuesday recovery; Wednesday glutes/legs; Thursday short easy run/walk; Friday recovery; Saturday controlled full-body strength; Sunday easy aerobic conditioning. These are opportunities, not a mandatory quota. Do not add missed sessions to a later day.

The earlier planner treated any adjacent leg-strength and running session as a conflict, which could remove Thursday while Friday was already protected. The foundation engine distinguishes normal controlled leg work from hard work, reported soreness, and long/hard running. It preserves a stable baseline and labels every adjustment with its reason. It never interprets a gym-attendance scan as known muscle loading.

## Evidence vs implementation choices
ACSM's 2026 position stand supports progressive resistance training, regular major-muscle exposure, and individualized load/volume. Training to failure and elaborate periodization are not prerequisites. A meta-analysis supports combining aerobic and strength training, with important distinctions for explosive strength. NHS beginner running guidance supports gradual run/walk and a day between runs; CDC's talk test supports a conversational intensity cue.

The exact six-session volume gate, 28-day load freshness window, two successful top-range sessions, two-minute run increase, and fatigue thresholds are conservative application heuristics, not validated physiological scores or guarantees of injury prevention.

## Progression and recovery
- Calibrate absent/stale weights; show the last comparable log without presenting it as an obligatory load.
- Build reps before load; require matching units/setup, controlled form, and easy/moderate effort for increase eligibility. An explicit user-entered equipment increment is required. Do not change a started prescription.
- Start with two working sets. Main upper/lower sessions can use three after sufficient recent recorded strength participation. Keep full-body work modest before Sunday.
- Two recent mostly-hard sessions reduce working sets for a review week. Pain, unusually poor recovery, overlapping strength work or excessive training frequency can suppress a session. Low sleep is context, not a diagnosis.
- Run on time and conversational effort, not the retired race-distance ramp. Only two similar easy, comfortable runs with positive next-day recovery feedback support an optional two-minute extension. Imported duration alone is insufficient. No speed/long-distance race block is generated here.
- Review every four weeks. Body weight is tracked separately and never rewards faster loss or increases the training dose.

## Data integrity and privacy
Migration archives only the specified withdrawn goal, preserving its ID, reflections and photos. Existing workouts, started sessions, units and actual measurements remain unchanged. The one-time migration uses a stable program ID and does not override a later user program.

Cloud conflict comparisons normalize this additive directive on both payloads and prior fingerprints. A genuine workout-data conflict still requires the existing explicit choice. No user workout history or health data is embedded in published code.

The homepage and month calendar share one tally function. Completion is based on available actual run/strength records, attendance is separate, and incomplete cloud/Strava data is labelled.

## Boundaries
The app supports planning, logging and rule-based coaching. It cannot assess live form, diagnose pain, verify user reports or provide medical clearance. The 2027 aspiration has no invented race date/distance and does not promise race readiness.
